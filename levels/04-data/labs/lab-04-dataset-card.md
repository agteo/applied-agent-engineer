# Lab 4: Dataset Card

## Objective

Write the document that lets someone decide **not** to use your dataset.

## Build

That framing is the standard. A card is finished when a stranger can read it and
conclude "this is not suitable for what I want" — which means the load-bearing
section is Limitations, and if it is the shortest thing on the page the card is
not done.

Eight sections:

| Section | The reader's question |
| --- | --- |
| Intended use | should I use this at all? |
| Sources | where did it come from, and can I check? |
| Schema | what shape are the rows? |
| Cleaning | what was removed, by what rule? |
| Metrics | how much of what? |
| **Limitations** | what will go wrong if I use it anyway? |
| Privacy | can I share this? |
| Downstream use | which split for which job? |

Four rules:

- **State scope in the first line.** "A teaching dataset, not production
  financial data" lets a reader stop reading immediately if it does not fit.
- **Sources are paths or commands, not descriptions.** "Curated from agent
  interactions" cannot be checked.
- **Generate the metrics from the build.** Hand-typed counts are correct on the
  day of writing and wrong from the next rebuild, silently, in the one document
  whose purpose is to be trusted without checking.
- **Disclose your synthetic fraction.** It is voluntary, it is usually the fact
  most likely to change a decision, and omitting it is not wrong in any
  checkable way while still being misleading.

Include a privacy line even when nothing is sensitive. Silence reads as
unchecked, not as clean.

## Deliverable

Submit a dataset card, **generated by your build script**, covering all eight
sections.

## Checks

```bash
# 1. It regenerates identically - that is what makes it trustworthy.
python3 path/to/your_builder.py --out /tmp/run-a
python3 path/to/your_builder.py --out /tmp/run-b
diff /tmp/run-a/dataset-card.md /tmp/run-b/dataset-card.md \
  && echo "OK: card is generated, not hand-edited"

# 2. Its numbers match the data it describes.
python3 - <<'PY'
import json, re
card = open("/tmp/run-a/dataset-card.md").read()
rows = sum(1 for l in open("/tmp/run-a/cleaned.jsonl") if l.strip())
claimed = re.search(r"cleaned rows: (\d+)", card)
print(f"card says {claimed.group(1)}, file has {rows}",
      "-> OK" if claimed and int(claimed.group(1)) == rows else "-> FAIL")
for s in ["Intended Use", "Sources", "Schema", "Cleaning", "Metrics",
          "Limitations", "Privacy"]:
    print(f"  {'OK ' if s.lower() in card.lower() else 'MISSING'} {s}")
PY
```

The lab passes when the card regenerates byte-identically, its counts match the
files, all eight sections are present, and your Limitations section is something
you would be comfortable having quoted back to you.


Read its Limitations section first. Two admissions there are costly and
necessary: that 100 of 152 rows are template-generated and cannot support an
improvement claim without held-out evaluation, and that correction targets are
"compact oracle summaries, not full human-authored ideal answers" — which is the
warning that training on them produces a terse model that passes every
deterministic grader and reads worse.
