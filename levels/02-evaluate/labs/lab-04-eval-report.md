# Lab 4: Eval Report

## Objective

Turn benchmark results into a report someone can make a decision from, and make
it regenerable.

## Build

Compare two StrongBench Expense Agent configurations. Change **one** thing, or
the result cannot be attributed:

- baseline prompt vs revised prompt
- one model adapter vs another
- keyword search vs improved search
- full toolset vs a deliberately broken one

That last option is the most instructive and the cheapest. A control with its
tools removed scores 0/30 here, and running one is how you find out whether your
benchmark can detect failure at all.

## Required Sections

1. decision summary — the recommendation, first
2. configurations compared, with version fields
3. headline metrics
4. per-slice breakdown
5. example failures, with values
6. judge calibration summary, with its sample size
7. limitations
8. recommendation: adopt, reject, or keep testing

Three rules the reference report follows:

- **Pair every rate with its denominator.** `receipt_lookup 3 / 10 = 0.300`, not
  `30%`. The reader can then calibrate without doing arithmetic.
- **Never report an agreement rate without its sample size.** They go on
  adjacent lines so the first cannot be quoted without the second.
- **List every failure, not a sample.** The failure section is the input to
  Level 3 diagnosis; truncating it silently decides what gets diagnosed.

## Deliverable

Submit:

- the report, generated by code rather than written by hand
- the raw score file
- run metadata: agent version, prompt version, model, benchmark version

## Checks

Your report generator passes when it is deterministic:

```bash
python3 path/to/your_report.py --out /tmp/report-a.md
python3 path/to/your_report.py --out /tmp/report-b.md
diff /tmp/report-a.md /tmp/report-b.md && echo "OK: byte-reproducible"
```

Then verify it carries what a decision needs:

```bash
grep -q "sample_size" /tmp/report-a.md && echo "OK: agreement has a denominator"
grep -qE "^\\| .* \\| +[0-9]+ \\| +[0-9]+ \\|" /tmp/report-a.md && echo "OK: slices show counts"
```

The lab passes when the report regenerates byte-identically, every rate carries
its denominator, all failures are listed with both values, and the first section
states a recommendation rather than a summary of what you ran.

## Reference

Write your own first, then compare against
[`evals/reports/sample-report.md`](../../../evals/reports/sample-report.md) and
the generator [`evals/report.py`](../../../evals/report.py).

```bash
python3 -m evals.runner --model scripted --report /tmp/reference.md
diff /tmp/reference.md evals/reports/sample-report.md && echo "byte-identical"
```

That the committed report regenerates byte-for-byte is what lets CI gate on it:
a diff means the *agent* changed. Hand-written reports cannot have that
property, which is the argument for generating yours.

Read the header block and notice `rubric_agreement_rate: 1.000` sitting directly
above `rubric_agreement_sample_size: 5`. Emitting them together is a decision
about what the report permits a reader to conclude — 1.000 on five examples has
a 95% interval running from roughly 0.57 to 1.00, and the adjacent line is what
stops it being quoted as certainty.
